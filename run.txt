ARYA — RUN & TEST RUNBOOK
=========================
Everything you need to run Arya locally and place a real test call to your own
number. Copy-paste the blocks in order. Lines starting with `#` are notes.

Test target baked in below:  name = "Rudra",  phone = 9766696568  (+91)


---------------------------------------------------------------------------
0) ONE-TIME SETUP  (needs your accounts — see README "Setup")
---------------------------------------------------------------------------
# Install dependencies
npm install

# .env.local must exist and be filled in (it's gitignored). Copy the template
# then paste your real values. Keys required (see .env.example for the full list):
#   LiveKit:   LIVEKIT_URL, LIVEKIT_API_KEY, LIVEKIT_API_SECRET,
#              LIVEKIT_OUTBOUND_TRUNK_ID, LIVEKIT_AGENT_NAME
#   Vertex:    GOOGLE_GENAI_USE_VERTEXAI=true, GOOGLE_CLOUD_PROJECT,
#              GOOGLE_CLOUD_LOCATION=us-central1, GOOGLE_APPLICATION_CREDENTIALS
#   Redis:     UPSTASH_REDIS_REST_URL, UPSTASH_REDIS_REST_TOKEN
#   Optional:  DAILY_CALL_CAP (default 20)

cp -n .env.example .env.local   # then edit .env.local with real values

# Sanity-check the env file exists (prints the KEY NAMES only, no secrets):
grep -oE '^[A-Z_]+=' .env.local | tr -d '='


---------------------------------------------------------------------------
1) STATIC CHECKS  (no accounts / network needed — run anytime)
---------------------------------------------------------------------------
npx tsc --noEmit     # typecheck
npm test             # unit tests (pure logic, no network)


---------------------------------------------------------------------------
2) CALL YOURSELF — THE WORKING LOCAL PATH  (two terminals)
---------------------------------------------------------------------------
# Upstash Redis is currently BLANK, so the web route /api/call throws
# (Redis.fromEnv() → checkGuardrails). Until Redis is populated, dial directly
# with the scratch _dispatch_once.ts script, which bypasses the web/guardrail
# layer and calls dispatchCall() the same way the route would.

# --- Terminal A: the agent worker (picks up the job and DIALS the call) ---
npm run agent:dev
# Wait until it logs that it's registered/connected to LiveKit before dialing.

# --- Terminal B: fire ONE outbound call to yourself ---
# Defaults to name="there", phone=+919766696568 (Rudra). Override via env.
CALL_NAME=Rudra CALL_PHONE=+919766696568 \
  npx tsx --env-file=.env.local _dispatch_once.ts
# Expected:  dialing: +919766696568   ...   DISPATCH_RESULT: {"ok":true,...}
# Your phone rings within a few seconds; Arya greets you first.
# NOTE: Twilio is a TRIAL account — the number MUST be a verified caller ID
# (Twilio console → Phone Numbers → Verified Caller IDs) or the SIP INVITE is
# rejected (sip status 400: 32100) and the phone never rings.


---------------------------------------------------------------------------
3) ALTERNATIVE — VIA THE WEB ROUTE  (only after Upstash Redis is populated)
---------------------------------------------------------------------------
# Once UPSTASH_REDIS_REST_URL + _TOKEN are set in .env.local, you can use the
# full route (guardrails + validation). Worker (Terminal A) must be running.
# --- Terminal B: the Next.js web app (serves POST /api/call + the UI) ---
npm run dev            # http://localhost:3000
# --- Terminal C: one-liner curl straight to the API ---
curl -sS -X POST http://localhost:3000/api/call \
  -H 'Content-Type: application/json' \
  -d '{"name":"Rudra","phone":"9766696568","consent":true}'
# Expected success:  {"ok":true,"roomName":"..."}
# Or through the UI: open http://localhost:3000 , enter name + 9766696568 ,
# tick consent , submit.

4) WHAT TO WATCH WHILE TESTING
---------------------------------------------------------------------------
# - Terminal A (worker) logs the call lifecycle + the lead:  [log_lead] {...}

---------------------------------------------------------------------------
5) COMMON NON-SUCCESS RESPONSES (from the curl in step 3)
---------------------------------------------------------------------------
# {"ok":false,"error":"consent_required"}    -> consent must be true
# {"ok":false,"error":"invalid_phone"}       -> must be a valid IN mobile (6-9 start)
# {"ok":false,"error":"number_rate_limited"} -> guardrail: same number too often
# {"ok":false,"error":"daily_cap"}           -> guardrail: DAILY_CALL_CAP hit today
# {"ok":false,"error":"killed"}              -> kill switch is on in Redis
# {"ok":false,"error":"dispatch_failed"} (502) -> LiveKit dispatch/env problem
# No ring but {"ok":true}                    -> worker (Terminal A) not running / not
#                                               registered, or SIP trunk misconfigured.
